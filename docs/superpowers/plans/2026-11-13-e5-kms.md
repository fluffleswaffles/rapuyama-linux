# E5 KMS Display Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The E5 panel becomes a KMS device (`/dev/dri/card0`, fbcon via DRM fbdev emulation) that runs weston + foot, with IRQ 146 instead of polling, an `rgb565` mode that gives SDL 1.2 games a native 16 bpp `/dev/fb0` at today's update rate, and a shorter welcome screen.

**Architecture:** A new DRM driver `drivers/soc/rapuyama/e5-display.c` (next to the E6's `videocore.c`, same helpers: `drm_simple_display_pipe`, GEM shmem shadow plane, damage clips, row diff, push thread) carries over the DMA/CPU push, panel sleep, DCS brightness and overlay from `rapuyama-e5-fb.c`, which stays in the tree untouched as a fallback for one release (`E5_FBDEV=1`). Pure pixel/band logic lives in a header tested on the PC. A small DRM core change lets the driver set its fbdev deferred-I/O delay (10 ms).

**Tech Stack:** Linux 6.12 DRM (simple KMS helper, GEM shmem, fbdev shmem emulation), C; POSIX sh (busybox ash) for scripts; Alpine armhf packages (weston, foot, xorg-server modesetting).

**Spec:** `docs/superpowers/specs/2026-11-13-e5-kms-design.md`

## Global Constraints

- No regression: console (fbcon, fonts, `font`), `brightness` (`/sys/class/backlight/panel`, 0..255), `blank` / consoleblank with any key waking, end key (`FBIOBLANK` on `/dev/fb0`), fn picture (`/sys/class/graphics/fb0/device/overlay` + `overlay_on`), X `browser`, simple mode (console only, all in RAM).
- A full-frame push stays about 18 ms; idle display = zero CPU (no polling, no timers when nothing changes).
- Commits do not wait for the push (E6 way): copy changed rows, wake the push thread, which merges frames.
- `rgb565` off by default (32 bpp, XRGB8888 as today); on via `e5_display.rgb565=1`.
- fbdev deferred-I/O delay 10 ms (today's `refresh_ms`), not DRM's 50 ms.
- weston + foot are never in the image: a start script + `apk add`; advanced setup only.
- Names and structure follow `videocore.c` (origin/e6) unless the hardware forces a difference: module params `rgb565`, `dma`, `dma_irq`, `busy_poll`.
- Commits as `git -c user.name=Kapina-Dev`, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; kernel commits in `linux/kernel/linux` (branch e5-port), top repo on e5-port; no push.
- Phone tests: one boot per batch, scripts served from the PC (`wget -qO- URL | sh`).

## Review Focus

1. Overlay with `rgb565=1`: e5-keyd writes an XRGB8888 picture (E5FB_OVL_SIZE = 320*4*120 bytes); in 16 bpp mode the driver must still accept that exact size and show it right. -> Task 3/5 test `overlay_rgb565_size` (host) + phone check.
2. A client commits a framebuffer of the other format (XRGB8888 plane fb while `rgb565=1`, or RGB565 when off): converted, never garbage, never rejected by fbcon. -> Task 1 tests `copy_xrgb_to_565`, `copy_565_to_565`, `copy_xrgb_to_xrgb`.
3. Blank while weston is DRM master (end key, consoleblank): no hang, no crash; panel state consistent when weston exits. -> Task 3 step + Task 9 phone check `blank_under_weston`.
4. DMA timeout / IRQ 146 never fires: falls back (polling, then CPU path) once, logs once, display keeps working. -> Task 4 test `irq_timeout_falls_back` (module param `dma_irq_timeout_ms` forced tiny on the phone) in Task 9.
5. Damage rect at the screen edge / zero-size / full-screen commit without clips: band math clamps to 0..240 rows, full commit without changed rows pushes nothing. -> Task 1 tests `band_clamp`, `no_change_no_push`.

### Task 1: Pixel and band helpers (host-tested)

**Files:** Create `drivers/soc/rapuyama/e5-display-core.h` (kernel tree), `linux/e5-display/tests/test_core.c`, `linux/e5-display/tests/run.sh`.

**Interfaces:**
- Produces (all `static inline`, header usable from kernel and host; host test typedefs `u8/u16/u32` and includes `<string.h>`):
  - `u16 e5d_xrgb_to_565(u32 xrgb)` (truncate 8->5/6/5, same as E6 `vc_565`)
  - `u32 e5d_565_to_xrgb(u16 p)` (expand with bit replication: r8 = r5<<3 | r5>>2, g8 = g6<<2 | g6>>4)
  - `struct e5d_band { u32 y0, y1; }` (empty when y0 >= y1); `void e5d_band_add(struct e5d_band *b, u32 y0, u32 y1)` (clamps to 0..240); `bool e5d_band_take(struct e5d_band *b, u32 *y0, u32 *y1)` (returns false when empty, empties it)
  - `void e5d_copy_rows(u8 *dst, u32 dst_pitch, u32 dst_cpp, const u8 *src, u32 src_pitch, u32 src_cpp, u32 x0, u32 x1, u32 y0, u32 y1, u8 *row_tmp, struct e5d_band *changed)`: converts src rows y0..y1 (cols x0..x1) into dst format (cpp 2 = RGB565, 4 = XRGB8888), writes a row only if it differs, adds the changed rows to `changed`.

### Task 4: IRQ 146 instead of polling
